# 小程序开发方案评估结论

> 评估日期：2026-08-04  
> 评估对象：《小程序开发待拍板问题清单-20260804》《小程序开发技术方案-20260804》  
> 评估方式：只读评估，未修改原方案文件

## 一、总体结论

本方案适合受控的内部 Demo，但目前不建议直接将技术方案从 `v0.1` 升级为 `v1.0`。

方案的工程分层、垂直切片、Mock 隔离、接口 smoke、弱网测试和按功能留痕方向基本合理；但安全边界、可执行工具链、接口契约冻结和回滚定义尚未闭合。当前更准确的定位是“可进入工程准备阶段的 Demo 草案”，不是已经完成确认的生产级技术方案。

## 二、P0：开工前必须补齐

### 1. 明确 Demo 安全边界

方案使用 HTTP IP 地址、Bearer Token，并且请求携带 `x-mock-user-*` 身份头。必须明确：

- 仅允许开发者工具本地 Demo，不得预览、上传体验版或向真实用户分发；
- Mock 头只能在开发构建启用，后端也应做环境白名单；
- 任何上线或真机真实数据场景必须切换 HTTPS；
- Demo 账号、数据、照片不得包含真实敏感信息。

### 2. 补齐 TypeScript 与测试工具链

目前只约定了 TypeScript strict、ESLint、Jest 和 `miniprogram-automator`，没有明确 `tsconfig`、Node/npm 版本、依赖锁定、构建命令、`tsc --noEmit`、测试命令、自动化工具版本和失败门禁。

否则“严格类型”和“每 commit 自动验证”无法被稳定执行。应先形成可运行的工程初始化清单和一键 preflight 命令。

### 3. 冻结输入文档与接口契约

方案依赖快照 R4、交接件和飞书接口文档，但当前方案包未包含快照和交接件，飞书文档也不是本地可锁定输入。

建议冻结一份带版本号和日期的接口快照，规定接口变更必须有负责人确认，并为 Mock 开关设置负责人、启用条件和关闭条件，避免“v1.3 基线 + Mock”长期漂移。

### 4. 重新定义“可回滚”

每功能一个 commit 只能回滚前端代码，不能回滚后端接口、配置、Mock 开关、缓存和演示数据。

Demo 阶段至少需要：环境配置切换、Mock 总开关、演示数据重置或造数脚本，以及禁止误连生产环境的启动检查。

## 三、P1：建议纳入 v1.0

- 建立页面、Spec 功能编号、接口、测试用例和验收证据的一一映射；commit message 不能替代验收台账。
- 增加直达链接、角色越权、后端 `403`、失效 Token 和重复提交测试。
- 在类型检查之外增加响应运行时校验，并明确超时、重试上限、退避、幂等键和错误码处理。
- 定义 Token、运单缓存和照片待重传队列的 TTL、容量上限、删除策略和异常清理。
- 明确图片压缩后的方向、证据质量、重复上传、队列满和文件清理规则。
- 处理轮询器重复启动、请求超时、退避、跨天和已读状态变化。
- 提供确定性演示数据和重置方式，避免阶段 6 临时造数成为交付瓶颈。
- 锁定 TDesign、微信基础库、开发者工具和 `miniprogram-automator` 版本，并确定最低验证设备范围。
- 增加请求 trace id、错误采集和关键操作审计，至少满足 Demo 故障定位。

## 四、文档内部一致性问题

1. 技术方案将远端仓库决策写为 `Q-B2`，实际问题清单为 `Q-A5`。
2. “core 五件套”实际列出 request、auth、poller、uploader、storage、mock 六个目录。
3. 文档称接口有 15 个域，但 `api/` 示例模块数量与 15 域未建立明确映射。
4. 已知缺口在问题清单称“四个”，技术方案附表实际包含 D1 在内的五项。
5. Q-A4 引用的“2026-07-30 决议”不在当前方案包中，追溯性不足。

## 五、拍板建议

- Q-A1：选 TypeScript。
- Q-A2：可选 TDesign，但应以样张验收组件覆盖度、包体和样式适配性。
- Q-A3：选样张先行。
- Q-A4：使用明确的绝对路径，避免仅依赖 `~` 的口头约定。
- Q-A5：Demo 可采用本地 Git，但必须有受控备份，备份中不得包含账号密码或 Token。

## 六、升级为 v1.0 的条件

完成四项 P0；补齐可运行的工程初始化和 preflight 命令；冻结接口快照及 Mock 清单；完成三页垂直切片；验证登录、角色路由、401/403、请求信封和关键上传链路；确认 Demo 环境不会误连生产或携带真实敏感数据。
