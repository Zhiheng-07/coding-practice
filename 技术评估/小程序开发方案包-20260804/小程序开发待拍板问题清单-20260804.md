# 小程序开发待拍板问题清单

> 2026-08-04 ｜ 配套《小程序开发技术方案-20260804》（v0.1）使用：A 类拍板完成后技术方案升 v1.0，开发工程即可初始化
> 分三类：**A=需你拍板的决策**（给出选项与推荐）｜ **B=需你执行/提供的事项** ｜ **C=知会项**（不需决策，影响排期，读过即可）

## A 类：需拍板的决策（5 项）

### Q-A1 开发语言：TypeScript 还是 JavaScript？

| 选项 | 说明 |
|-|-|
| **A. TypeScript（推荐）** | 接口文档 15 域的字段/枚举落成类型定义，Claude Code 写错字段在编译期报错而非运行时才发现；后端校验严格（多传字段直接 400），类型约束是最便宜的自动防线；大厂标配 |
| B. JavaScript | 少一层编译链，但失去全部类型防线——对无法人工读代码的场景不划算 |

**影响**：全部代码文件形态；开工前必须定，中途切换成本高。

### Q-A2 UI 组件库：用哪个？

| 选项 | 说明 |
|-|-|
| **A. TDesign（腾讯官方，推荐）** | 与微信生态贴合、维护活跃、TS 支持好；MP-交互规范要求的卡片/表单校验/actionSheet/toast/骨架屏/空态/图片预览大半有现成组件 |
| B. Vant Weapp（有赞） | 同样主流可用，风格偏电商 |
| C. 纯手写 | 视觉完全可控，但工作量大、样式质量难保证，Demo 项目不推荐 |

**影响**：全部页面的视觉底子与开发速度；与 Q-A3 联动。

### Q-A3 视觉基线策略：先出样张确认，还是直接按组件库默认铺量？

| 选项 | 说明 |
|-|-|
| **A. 样张先行（推荐）** | 垂直切片阶段（登录页+运单列表+详情共 3 页）先做出可看的样张，你在开发者工具里过目认可视觉风格后，再批量铺其余 14 页——返工范围锁定在 3 页 |
| B. 直接铺量 | 快，但 17 页做完你不满意视觉时全量返工 |

**背景**：MP-交互规范只管交互条款，视觉规范原文写明「随原型阶段补充」——即目前**没有视觉稿**，视觉事实上由本次开发定义。基础口径已定的部分：状态色语义承接 Web（进行中蓝/完成绿/驳回红/待处理橙）。

### Q-A4 代码工程的位置与命名？

需要你给一个**独立文件夹路径**（2026-07-30 决议：独立文件夹 + git init + 独立 CLAUDE.md，不放在 Web多式联运 目录内）。

**建议**：`~/Desktop/多式联运小程序/`（与主项目平级，名称直观）。你也可以指定任意其他路径/名称。

### Q-A5 代码仓库要不要推远端？

| 选项 | 说明 |
|-|-|
| **A. 仅本地 git + 定期备份（推荐）** | Demo 阶段够用；甲方项目代码不出本机，无泄露面。备份可打 zip 存本地/网盘 |
| B. 推私有远端（GitHub 私有仓库 / 内网 git） | 多机协作或给工程师看代码时方便；若走内网 git 需向工程师确认是否有现成服务 |

**影响**：不阻塞开工（可先本地、后补远端），但涉及"代码是否离开本机"，属于你该拍的边界。
