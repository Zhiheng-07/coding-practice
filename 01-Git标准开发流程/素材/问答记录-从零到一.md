## 问题 1

**Q：假设你现在电脑上有一个全新的文件夹，里面已经写了几个文件，但还从来没有跟 Git/GitHub 打过交道，接下来要做哪几步才能让这份代码「进入」GitHub 上的一个仓库？**

**A（当时的理解，原话）：** 「在 GitHub 新建项目，然后本地文件夹做 git 初始化，最后想办法让两者进行连接。」

大方向对——「远程建仓库」「本地初始化」「两者关联」确实是三个动作，但每个动作里都有没拆开的细节，往下几个问题逐一挖。

## 问题 2

**Q：在 GitHub 网页新建仓库时，会不会勾选「Add a README file」？**

**A（当时的理解）：** 「不知道每个项目文件都有 README file，勾或不勾不清楚。」

**实际：**

- README 不是「每个项目文件都有」的东西。它是仓库**根目录下的一份特定文件**（`README.md`），一个仓库通常只有一份，写给**人**看的说明书——项目是做什么的、怎么装、怎么跑起来。Git 本身不强制要求有它，纯属约定俗成；GitHub 网页会自动把它渲染显示在仓库首页，这也是为什么看起来「每个项目都有」。
- README 会随项目迭代持续更新：加了新功能、调整了安装步骤，就跟着改一次，改的方式和改任何其他文件一样，走 `add` → `commit` → `push`，没有特殊流程。
- 它不跟着分支或功能走——一个仓库只有一份，活在你当前检出的那条分支上，除非你的改动恰好也碰了这个文件，否则合并时不会牵扯到它。
- **勾不勾「Add a README file」的真实后果**：勾了，远程仓库刚建好就已经有一个 commit（GitHub 自动生成的那个）；不勾，远程仓库完全空，连一次 commit 都没有。这个差别直接决定后面能不能顺利关联——如果本地已经 `git init` 并自己 commit 过，远程又勾了 README，两边各有一条独立历史、没有共同祖先，直接关联会报错，需要额外处理（见问题 4）。

## 问题 3

**Q：「本地文件夹做 git 初始化」，具体要敲哪条命令？在哪执行？**

**A（当时的理解）：** 「我理解要敲 git init，但是不确定是要进 Claude Code 前敲还是 cd 打开文件夹就敲。」

**实际：** `git init` 和用不用 Claude Code / Codex、用什么编辑器完全无关，它是纯终端（shell）操作——`cd` 进入那个项目文件夹，在终端里敲 `git init` 就完成了。这一步只在乎「你当前站在哪个文件夹」，跟你之后打不打开 AI 编程工具没有任何关系。

## 问题 4

**Q：如果反过来——远程已经建好一个空仓库（还没勾 README），本地要开始写代码，该怎么操作？**

**A（当时的理解，原话）：** 「从 GitHub 这个远程仓库点击 Fork 到自己的账号，然后克隆到本地进行开发。」

**实际：这里的 Fork 是多余的一步。** 回忆模块 01 正文已经讲过的一条：**fork 解决的问题是「你没有这个仓库的写权限」**。但这个场景是——仓库是你自己或团队新建的，你本来就是 owner 或协作者，天生有写权限。这种情况直接：

```bash
git clone <仓库网址>
```

一步到位，不需要 fork 这道中间手续。fork 只用在「给别人的开源项目提代码，但自己没有写权限」的场景（对应模块 01 正文步骤 2 深入部分的完整 fork 工作流）。

顺带确认：`git clone` 是终端命令行操作，和 `git init`、`git pull` 一样，不是网页点按钮。

**若本地文件夹已经先写了点东西（不是从零 clone），事后才想关联到这个远程空仓库**，则是：

```bash
git remote add origin <仓库网址>
git pull origin main --allow-unrelated-histories   # 双方历史没有共同祖先时才需要这个参数
```

## 问题 5

**Q：用 GitHub CLI（`gh`）能不能一条命令搞定「建仓库 + 关联本地」？**

**A（当时的理解）：** 「我觉得很可能就是一条命令就可以解决」——方向对，但不清楚命令里需要给哪些信息。

**实际：** 一条命令要同时完成「建仓库」和「关联本地」，至少要告诉它：仓库名、可见性（public/private）、「拿当前文件夹内容作为仓库源」这个动作、以及建完要不要立刻推送。对应：

```bash
gh repo create my-project --private --source=. --remote=origin --push
```

这条命令等价于「网页建空仓库 + `git remote add origin` + `git push -u origin main`」三步的合并版。

## 问题 6

**Q：默认分支名会不会「两边对不上」？**

**A（当时的理解）：** 「之前没注意过这个问题。」——真实盲点，值得写进正式内容。

**实际：** GitHub 网页新建仓库时，默认给的分支名是 `main`；但本地 `git init` 出来的分支名，在较旧的 Git 版本上默认是 `master`，需要手动改名对齐：

```bash
git branch -M main
```

如果本地 Git 版本较新、或者已经执行过 `git config --global init.defaultBranch main`，`git init` 出来就直接是 `main`，不会遇到这个问题——但不能假设所有人的环境都配置过，第一次全新初始化时保险起见都过一遍这条命令。

## 小结：三个场景的完整命令串

**场景①：全新项目，本地先有文件夹，远程还没建**

```bash
cd my-project
git init
# 建 .gitignore（在第一次 commit 之前）
git add .
git commit -m "init: 项目初始化"
git branch -M main
# GitHub 网页新建一个空仓库（不勾 README，避免历史冲突）
git remote add origin <仓库网址>
git push -u origin main
```

**场景②：远程已建好空仓库，本地从零开始**

```bash
git clone <仓库网址>
```

（若本地已有文件、不是从零开始，改用 `git remote add origin` + `git pull origin main --allow-unrelated-histories`）

**场景③：gh CLI 一条命令**

```bash
gh repo create my-project --private --source=. --remote=origin --push
```
